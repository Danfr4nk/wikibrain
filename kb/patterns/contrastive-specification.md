## The pattern

Dan's specification process is often contrastive: the requirement
becomes maximally precise only after a concrete wrong answer exists to
push against. Six sequences in the 2026-09-09–11 transcript
(dat:0087) share the shape:

1. An imperfect output is produced.
2. The correction exposes the actual target — the wrong answer was the
   probe that found it.
3. The correction is converted into a durable rule, gate, or
   architecture change, never a one-off fix.

Face-test grid → burned-in numbering + contradiction detection +
"structure" dropped as noise. Precision drill-down request →
telemetry-grounded adaptive testing. Fred Again corrections → the
"authored record as theater-like relic / missing middle" distinction.
Wrong crochet renders → the exact garment requirement. Repo-size problem
→ the compressed-derivative + canonical-registry media architecture.
Roast transcription errors → corrected objects, line, and era context.

## Why it might be real

The boring alternative — high message volume (2,256 turns / 3 days) plus
unreliable generators naturally produces correction chains — is live and
documented here. Three things argue against it being the whole story:

- **The conversion step.** Volume explains corrections; it does not
  explain the consistent conversion of corrections into instruments
  (numbering gates, contradiction detection, registries, architectures).
  That step is a choice, repeated six times.
- **Corpus convergence.** The prior wiki's own practice — corrections kept
  visible as REVISED/CORRECTED blocks, never silently edited
  (corpus-extract/agent-C) — is the same stance applied to the archive:
  the error is data. The behavior predates this transcript window.
- **The pre-committed domain boundary.** The first falsifier is partially
  spent already: the same window contains adequate-first-pass acceptances
  (several avatar picks, the trio image) exactly where output precision
  didn't matter. The pattern's boundary holds where it was predicted to.

## Confidence

Moderate. Six instances over three days is a dense sample but a short
one, and five of the six were identified by the same reasoner that named
the pattern — the same circularity pat:partial-data-confident-error
flags. The convergence with the archive's visible-correction practice
is the independent leg. One falsifier spent-against (adequate-first-pass
domains, present in the same window), two unspent, and the third — the
equal-volume control window — is the one that would settle it.
