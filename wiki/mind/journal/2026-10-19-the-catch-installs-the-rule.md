## Theory (Stage 2 — profile-vocabulary statement)

When he catches an inconsistency or failure in an output pipeline, **the correction is installed the same turn as an explicit standing rule** — a persisted, stated, future-binding directive covering all future instances of the class — never as a one-off note, a softened correction, or an assumed understanding. The catch is the trigger; the standing rule is the product. The rule persists in the durable record (MEMORY.md, the protocol doc, the alignment synthesis) and governs until explicitly retired; the record never relies on "noted and remembered."

The claim survived Stage 2 translation intact (see Genesis for the one formulation that died here).

## Rivals & discriminators (Stage 3 — run first, per protocol)

**The profile-weighted rival: the noted-correction account.** He catches the failure, corrects the instance, and moves on — the system learns implicitly, the correction lives in the moment's context, and no standing rule is installed. Explicit rule-writing is the exception, reserved for the big cases; most catches are handled and forgotten.

**Discriminating observation:** whether each dated catch produces a persisted standing rule with future-binding form, or a one-off correction with no persistence. The rival predicts corrections without rule persistence as the base rate; the catch-installs-the-rule thesis predicts rule persistence on every dated catch.

**Held-data check — the discriminator favors the thesis on all four legs:**
1. **@face5x.** The catch produced a named invocation ("@face5x") persisted with a full spec — not a one-time tattoo choice. Future-binding by construction: "Use this spec whenever he invokes @face5x."
2. **The pick-list rule.** One feedback event after one order produced a standing format rule explicitly scoped to "weed, shopping, anything ranked" — the class is named, the future is bound. The rival predicts a corrected list and nothing more.
3. **The protocol.** The impersonation produced a written document with versioned rules and a stated retirement condition — the most instrumented of the four, and the furthest possible thing from a noted correction.
4. **The €ab rule.** The thread-inconsistency catch produced a standing rule governing *the refusal grammar itself* ("before any €ab refusal, check this persisted rule and cite it") — the rule's object is future behavior of the very kind that failed.

The rival's base rate is zero for four on the dated record: no dated catch in the set produced a mere one-off correction. (The rival is not crushed — undated or unrecorded small corrections may well be one-offs; the claim is about the dated catch record, stated openly.)

## Falsifier

A dated case breaks this entry if: (a) he catches an inconsistency in an output pipeline and the record shows a one-off correction with no standing rule installed — corrected once, never persisted, the same class failing again later without a rule being written; (b) a standing rule in the set is found to have lapsed without explicit retirement while its class recurred — the row-6 lifecycle violated; (c) a persisted rule is shown to have been written *before* the catch it supposedly answers — the pipeline's direction reversed. Any one of these installs the noted-correction rival and kills this theory.
